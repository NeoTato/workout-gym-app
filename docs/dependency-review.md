# Foundation dependency review

SDK 58 is selected after the user's physical iPhone reported that its installed Expo Go requires SDK 58. This supersedes the earlier SDK 57 transition assumption. Expo, Router, React Native, animation peers, fonts, and test tooling follow the SDK 58 compatibility requirements. React and React DOM are both 19.3.0. The React Native Testing Library renderer is pinned to 1.3.1 to match that React generation, and the Jest Expo server renderer is explicitly pinned to React Server DOM 19.3.0 so npm cannot select a later incompatible React patch.

The original SDK 57 dependency tree had unresolved high-severity advisories. The coordinated SDK 58 upgrade removes those high-severity findings without transitive overrides or forced audit fixes. Low/moderate findings and deprecation warnings remain; this is not a clean-all-severities audit. CI retains the independent `npm audit --audit-level=high` gate, with no threshold change or suppression. Physical iPhone/Android validation and user PR review are still pending; the PR remains a draft until reviewed.

- Previously: `decode-uri-component` through `query-string@7.1.3` / Expo Router allowed excessive work from malformed percent-encoded input. The SDK 58 Router uses an updated dependency chain. The fixed decoder's ESM boundary is handled by upstream, not an untested local override. [Upstream advisory](https://github.com/advisories/GHSA-qr28-fpjm-wq7f).
- Previously: Zod 3 through Expo CLI was reported for oversized-collection validation. SDK 58 changes the CLI dependency tree; no cross-major Zod override is added locally. [Upstream advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
- Additional low/moderate findings affect build/test/lint dependencies including glob, minimatch, and deepmerge. Full results remain visible through `npm audit`. These are not claimed to be fixed or proven harmless.

No backend, imported workout files, user query parsing, or personal workout database is added in this PR, but that limited current exposure is not a reason to suppress findings. `npm audit fix` was attempted without force on SDK 57 and did not resolve its SDK-constrained findings. SDK 58 is a deliberate, coordinated update prompted by confirmed device compatibility, following [Expo's upgrade guidance](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/). Do not skip audit jobs or add untested global overrides just to get green checks.

Keep reviewing remaining low/moderate findings and refresh this document when applying fixes; counts and affected dependency paths can change as advisories are updated. Deprecation warnings from nested tooling packages do not mean installation failed, but they are maintenance work to track rather than proof of safety.
